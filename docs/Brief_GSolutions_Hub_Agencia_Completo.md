# Brief de Diseño — GSolutions Hub
## Documento para Agencia / Marketing

**Marca madre:** GFourmis  
**Ecosistema / Marketplace:** GSolutions Hub  
**Versión:** 1.0  
**Estado:** Base para diseño, validación visual y producción de piezas

> **Principio rector:** Diferentes soluciones. Una misma tecnología. Un mismo ecosistema.

---

## 1. Resumen ejecutivo

GSolutions Hub es el ecosistema de soluciones, servicios, módulos y casos de uso de GFourmis. Su objetivo es centralizar en una única experiencia el portafolio que GFourmis ofrece a empresas, permitiendo descubrir, entender, solicitar, adquirir y acceder a distintas capacidades sin que cada solución se perciba como un producto aislado.

GSolutions Hub no reemplaza la identidad de GFourmis. GFourmis continúa siendo la marca madre y GSolutions Hub funciona como el punto de encuentro del portafolio.

---

## 2. Objetivo estratégico

Convertir capacidades ya desarrolladas por GFourmis en un portafolio:

- Estandarizado.
- Reutilizable.
- Fácil de descubrir.
- Fácil de comercializar.
- Fácil de habilitar.
- Escalable.
- Integrable con AWS Marketplace.
- Preparado para aprovechar funding, créditos e incentivos de AWS cuando corresponda.
- Potenciado por automatización e inteligencia artificial.

La intención no es únicamente mostrar productos. El Hub debe evolucionar hacia la plataforma comercial y operativa del portafolio de GFourmis.

---

## 3. Concepto rector de marca

### Concepto principal
**Tecnología que avanza contigo.**

GFourmis no solo ofrece tecnología, sino un ecosistema de soluciones que acompaña el crecimiento y la transformación de sus clientes.

### Principio de construcción
- **Icono + nombre = diferenciación.**
- **Sistema visual = pertenencia.**

Cada solución debe ser reconocible por sí sola, pero todas deben sentirse parte de una misma familia.

## 9. Sistema visual

### Paleta

| Color | HEX | Función |
|---|---|---|
| Ámbar | `#FFA800` | Energía, innovación, énfasis |
| Naranja | `#FF3D00` | Tecnología, transformación, acción |
| Tinta | `#0B1A1A` | Profesionalismo, profundidad, fondos oscuros |
| Blanco | `#FFFFFF` | Claridad y contraste |

### Gradiente
`#FF3D00 → #FFA800`

**Regla:** el gradiente es una firma visual, no un relleno obligatorio.

### Tipografía
**Inter**

- Nombre de solución: ExtraBold / Bold.
- Títulos: Bold / ExtraBold.
- Subtítulos: SemiBold.
- Texto: Regular.
- Descriptor: Medium.

| Descriptor | Inter Medium 11 px, `#78808E` |

### Versiones
**Fondo claro:** isotipo a color, texto oscuro.  
**Fondo oscuro:** isotipo a color, texto blanco, descriptor ámbar.

El isotipo de GSolutions Hub no debe convertirse en el icono de todas las soluciones.

## 11. Sistema de iconos de solución

Cada solución puede tener su propio símbolo.

Debe:

- Ser simple y reconocible.
- Funcionar a tamaños pequeños.
- Funcionar en formato cuadrado.
- Mantener relación visual con GFourmis.
- Mantener lenguaje geométrico y tecnológico.
- Funcionar en fondo claro y oscuro.
- Evitar exceso de detalle.

No deben ser iguales, pero sí parecer de la misma familia.

Aplicaciones a validar:
Marketplace, favicon, header, card, fondo claro, fondo oscuro, app/avatar y presentación.

---

## 12. Sistema de fondos

### Fondo claro
Uso: Marketplace, paneles, documentación e interfaces de lectura.

- Blanco o gris muy claro.
- Símbolos naranja/ámbar.
- Texto oscuro.

### Fondo oscuro
Uso: portadas, landing pages, hero sections y comunicaciones de alto impacto.

- Tinta / azul oscuro.
- Símbolos naranja/ámbar.
- Texto blanco.
- Gradientes controlados como iluminación.

## 13. Experiencia del Hub

La experiencia debe separar claramente:

### Solutions / Hubs
Soluciones completas que agrupan varios módulos, servicios, journeys o casos de uso.

#### GAIA
GFourmis Adoption and Innovation Accelerator.  
Puede contener Kiro Adoption Accelerator, Amazon Quick Adoption, FinOps Adoption, AI Development Adoption y futuros programas.

#### Architecture Quality
Hub orientado a calidad, revisión y validación de arquitecturas.  
Puede contener AQR, WAR, Infratest y futuras evaluaciones de calidad.

#### Ready to Deploy
Catálogo de casos de uso preconstruidos que pueden adaptarse rápidamente.  
Ejemplos: Call Insights AI, Document Intelligence, Knowledge Assistant, SFTP, Web Hosting, Notification Healthcheck.

#### GSmart
Hub orientado a automatización inteligente del ciclo comercial y de delivery mediante IA y agentes.  
Puede incluir Starting, GProject y agentes especializados.

## 14. Servicios independientes

### Startup Advisory
Asesoría puntual para startups que necesitan acompañamiento sobre AWS.

### Migration Ready

Acompañamiento en definición y diseño de arquitecturas de IA sobre AWS.

## 15. Estructura visual de las Cards

Cada card debe contener, según aplique:

1. Icono.
2. Categoría.
3. Nombre.
4. Descripción corta.
5. Dato relevante.
6. Estado.
7. CTA.

**Estados:** Disponible / Habilitado / No habilitado / Piloto / Próximamente / Requiere solicitud / Funding potencial / Elegible sujeto a validación.

**CTA:** Entrar al Hub / Ver detalle / Solicitar acceso / Solicitar solución / Solicitar assessment / Adquirir.

- Servicios AWS utilizados.

## 17. Estrategia de acceso y suite

GSolutions debe sentirse como una única suite aunque cada solución funcione técnicamente de forma independiente.

### Principio de experiencia
**Una empresa. Una identidad. Toda la suite.**

La empresa es la entidad principal.  
Las soluciones o servicios se habilitan a la organización.  
Los usuarios son miembros de esa organización y reciben acceso según roles o espacios.

El diseño debe evitar transmitir que cada producto requiere una cuenta independiente.

---

GSolutions debe estar preparado para convivir con AWS Marketplace.

- Contratación directa.
- Marketplace.
- Trial.
- Piloto.
- Funding.
- Programa de adopción.
- Partner solution.
- Servicio bajo solicitud.

La UI debe poder representar estos estados de forma consistente.

## 19. Inteligencia Artificial

La IA es una capacidad transversal del ecosistema.

El sistema debe estar preparado para representar:

- Agentes.
- Copilots.
- Automatización.
- Analítica generativa.
- Recomendaciones.
- Automatización de procesos.

No todas las soluciones deben parecer “productos de IA”. La identidad visual debe comunicar tecnología avanzada sin caer en clichés excesivos.

## 22. Qué debe evitar la agencia

- Cambiar arbitrariamente la paleta por solución.
- Crear una tipografía diferente para cada solución.
- Convertir cada producto en una submarca desconectada.
- Utilizar la hormiga como icono obligatorio.
- Modificar el logo principal de GFourmis.
- Reemplazar el identificador propio de una solución por el logo de GFourmis.
- Exceso de efectos 3D.
- Sombras demasiado marcadas.
- Saturar de naranja las interfaces.
- Crear iconos demasiado complejos.
- Usar iconos AWS como identidad de una Solution.
- Comunicar funding o créditos como garantía.

## 24. Regla para nuevas soluciones

1. Definir qué problema resuelve.
2. Definir si es Solution, Servicio, Módulo o Use Case.
3. Definir un nombre propio y diferenciable.
4. Crear su símbolo dentro del lenguaje del ecosistema.
5. Aplicar la paleta global.
6. Mantener Inter.
7. Construir el identificador: `[ICONO] + [NOMBRE] + by GFourmis`.
8. Validar Marketplace, favicon, header, card, fondos y tamaño pequeño.
9. Definir CTA.
10. Definir cómo vive dentro de GSolutions Hub.
